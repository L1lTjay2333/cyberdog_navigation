# 网页相机连接与采集前检查（2026-10-28）

## 使用方式

刷新8766页面，新增“连接/检查深度相机”按钮及相机输入状态。

1. 机器人开机或相机输入未就绪时，点击连接按钮。电脑会检查原厂相机，必要时在空闲、没有对齐相机占用的条件下，通过原厂生命周期完成配置/激活。
2. 若深度图已恢复、原厂任务空闲但缺少vodom位姿，连接按钮可调用既有MappingBridge准备扫描输入，保留旧地图备份；随后再次检查实际数据。
3. 状态显示“深度图与同时间位姿已就绪”后再开始采集。
4. **每次**点击静态或移动采集，后台都会重新执行只读输入检查，不依赖上次连接成功的缓存。检查通过后才创建新会话并替换当前显示模型。

连接按钮不开始模型采集，也不发送机器人运动。连接可能启动原厂扫描输入，因此请勿同时在手机上启停建图/导航；手机仍可用于随后人工遥控。已有正常扫描任务可直接复用，其他任务或相机所有权冲突时不会自动停止或接管。

## 就绪条件

- 获取原厂相机生命周期和任务状态。
- 至少三帧不同、递增原始时间戳的新鲜有效深度图；支持现有16UC1/32FC1米制深度，不只依据active状态或话题存在。
- 深度图与CameraInfo的帧名、尺寸、内参、编码、行布局及时间差符合采集要求，抽样深度存在有效范围内的数据。
- 使用原始深度时间戳查找完整camera→vodom位姿，至少三帧配对成功；不能用最新TF替代。
- 检查结束时原厂扫描任务仍有效。

没有深度帧、位姿缺失、任务被手机切换、SSH失败或响应不确定时明确显示原因；不会盲目重试相机切换或任务请求。

## 交互与取消

准备和采集请求互斥，准备中禁用连接/开始按钮。停止按钮可取消电脑侧检查或采集，不让机器狗停车，也不撤销已经发出的原厂初始化/扫描请求。若正在等待扫描请求响应，取消需等当前接口返回；再次开始前仍重新检查状态。

检查失败保留上次模型、会话和原始数据，不再创建一个0帧会话覆盖屏幕。正常采集过程中发现输入失效，也会将相机就绪状态改为未就绪。状态显示最近一次核验结果，不是常驻高频硬件监视器；重启或手机操作之后应重新点击连接，开始按钮也会强制复查。

## 实现位置

- `tools/reconstruction_input_probe.py`：临时发送到机器人执行的Python 3.6兼容检查，仅有传感器订阅、TF查询和限定的原厂相机/状态服务。
- `tools/reconstruction_readiness.py`：电脑侧SSH检查与显式连接准备、审计记录。仅显式连接允许空闲任务下启动扫描，普通开始采集前检查为只读。
- `tools/reconstruction_server.py`：`/camera/connect`、准备互斥、每次采集前检查、失败保留模型。
- `reconstruction.html`：连接按钮与就绪/失败说明。

没有新增固件、修改原厂控制源码或运动参数。
