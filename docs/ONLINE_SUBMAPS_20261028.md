# 在线分块融合接入（2026-10-28）

## 原因与修改结果

原网页逐帧接收并融合深度数据，但将全部体素留在一个字典内，超过20万体素就中止；这是原型保护值，不是相机或机器狗的硬件点数限制。此前分块仅用于离线实验，本轮已接入真实采集服务的移动模式。

现在按容量顺序分块：接收原深度和同时间位姿 → 当前块融合 → 满块以NPZ保存到电脑 → 以前一帧作为边界重叠观测，继续新块。旧块不覆盖。静态模式保留原行为。

没有加入几何纠偏、全局优化、TSDF或回环。在线仍由原厂vodom位姿引导；容量问题的解决不等于转动精度问题已经解决。

## 运行边界

| 项目 | 当前值/行为 |
| --- | --- |
| 单块体素 | 200,000，满后切换新块 |
| 最大封存块数 | 64 |
| 分块NPZ文件配额 | 512 MiB |
| 网页预览 | 最多30,000点，完整点另存磁盘 |
| 单块预览缓存 | 最多30,000点，最多64个封存块 |
| 移动采集时长 | 可选60 / 180 / 300秒，服务最大300秒 |
| 静态采集时长 | 最大60秒，默认30秒 |
| 移动原始顺序归档配额 | 256 MiB；满后标记不完整，不虚报全量 |
| 原3米累计路程/2米离起点限制 | 在线分块模式移除，旧离线MovingModel仍保留 |
| 单步跳变、运动过快、时间断档 | 仍拒绝融合并停止采集；不控制机器人 |

磁盘配额针对分块NPZ，原始归档及PLY导出另占空间；不能将512 MiB解释成整个会话的总磁盘占用上限。翻块时旧块和候选新块字典会同时存在，峰值内存不等于一个块；但不随整个房间点数无界增长。封存预览缓存的点坐标上限约46 MiB，另有字典、数组与导出缓冲。

有界资源保护仍然必要；本轮解决的是“单块满就结束全部扫描”，不是承诺无限时长和无限磁盘。

## 显示、计数、导出和恢复

- 网页区分“当前块体素”“已落盘块数”和总分块稳定点数，不再把累计体素数除以单块上限制造误解。
- 预览同时保留封存块与当前块，按总显示点数抽样；预览抽稀不改磁盘原始块精度。
- 稳定点仍要求在所在块内至少两帧支持。块边界保留一帧重叠，边界稳定点可能重复；未做全局去重或跨块完整支持合并，网页和PLY均明确标注。
- PLY按冻结的导出快照逐块写出，避免把整个模型一次性拼成大字节串。导出快照不会随随后到来的新帧改变，正文点数与头部一致。
- HTTP下载和磁盘保存都使用分段输出。兼容旧小模型的`ply()`帮助函数仍可生成字节串，但在线导出路径不使用它。
- 正常结束时封存最后一块并保存manifest；服务重启可从manifest恢复抽样视图及完整导出，不重新连接机器人。
- 本轮不是进程崩溃后自动续扫功能：没有完整manifest的中断会话不能自动恢复；已生成的块文件仍在磁盘。新会话始终创建新目录，不在旧目录续写。

## 验证证据

1. 67项三维相关单元测试通过。新增覆盖在线采集服务的模拟帧流、连续翻块、完整导出、导出期间新帧到来、恢复不连接机器人、预览限额、运动跳变与时长边界等情况。
2. 用真实保存的44帧，以每块80,000体素强制重放在线模型：完整处理44帧，生成4块，峰值当前块79,418体素，NPZ合计7,115,448字节。
3. 重放导出72,428个分块稳定点、PLY 2,262,936字节，恢复后点数一致。该点数含边界重复，不能与旧模型66,799个全局单块稳定点直接比较并宣称精度提高。
4. 该44帧离线重放约3.09秒，不能作为无线采集实时吞吐或长时间稳定性验收。
5. 网页全拦截测试验证分块状态、默认60秒和可选300秒请求，无真实机器人请求。
6. 当前真实网页GET-only检查通过，旧44帧模型66,799点显示/导出正常，无POST、无运动或采集启动。

本地重放证据：`evidence/streaming_replay_20261028/`；真实网页检查沿用`tests/reconstruction_browser.cjs`，新分块页面逻辑见`tests/reconstruction_moving_browser.cjs`。
