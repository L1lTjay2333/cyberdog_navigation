# 三维建模算法增量与离线验证（2026-10-27）

## 本轮交付

已实现电脑端的分块存储、局部点到平面配准及可复现重放工具。分块与配准仍是**离线实验入口**，没有替换当前网页的融合算法。新增的完整帧归档已接入采集源码，下次重启建模服务后生效；本轮没有重启服务或采集新数据。机器人可以保持关机，原厂控制、导航和运动接口未改。

## 容量管理

`tools/reconstruction_submaps.py` 将当前块封存为包含点坐标与观测帧支持数的 NPZ，然后开启下一块。块边界保留前一帧作为重叠观测。已有块不被覆盖；一次输入及重叠帧无法装入新块时明确报错，不丢弃旧表面。默认每块20万体素，最多64块、512 MiB文件配额；这些是实验保护值，尚非房间扫描验收配置。

保存的7个真实关键帧用**每块4.5万体素**重放，成功生成3块，分别40,879、41,216、26,957个体素，合计文件3,054,992字节。原来这7帧单块共占71,144个体素；本次实验验证可以越过单块上限继续处理，没有提高单块限额。

边界点可能存在于两块中，因此各块点数之和不是全局去重点数。至少两帧支持的判定目前在块内进行，分块会改变支持统计，不能据此宣称与原单块模型完全等价。尚未实现跨块支持合并、回环后重积分、全局网格或网页分页加载。翻块时旧块与候选新块字典会同时存在，单块上限不是进程峰值内存上限。

证据：`evidence/reconstruction_experiments/20261027_submaps_final/replay_report.json`。

## 局部配准与质量检查

`tools/reconstruction_registration.py` 对已经由原厂同时间完整位姿变换到 vodom 的点云，估计剩余刚体偏差。使用已有 NumPy / SciPy，无需在机器人上安装或编译新模块。

流程：2 cm降采样、每云最多6000点 → 局部邻域PCA法向 → 最近邻对应 → 鲁棒加权点到平面迭代 → 几何可观测性与留出点质量检查。2 cm为配准计算的采样大小，不改变原始深度尺度或1 cm融合体素。

当前实验阈值：

- 对应距离小于8 cm，初始/最终有效对应比例至少45%；每云至少100点。
- 法向邻域16点，邻域半径上限15 cm，排除局部几何不可靠的点。
- 加权雅可比最小/最大奇异值比例至少0.01；单一平面等退化情形拒绝估计完整六自由度。
- 每次迭代残差纠偏不超过3 cm / 3°，累计相对点云质心不超过5 cm / 5°。
- 每5个源点留出1个用于检查；最初留出有效点至少95%需在候选纠偏后保持有效。留出点仍来自同一采集云，不是独立测量真值。
- 留出点平面残差RMSE最多15 mm；候选更新须有改善，或原始观测已经一致且候选改动很小，此时保持单位变换、不施加无意义微调。
- 拒绝时返回单位变换。重放入口停止几何融合，不悄悄切回未经检查的里程计叠加。

这些阈值是实验参数，没有真实大角度转动验收依据，不应为了让现有样本通过而逐项放宽。5°是**位姿初值之外的剩余纠偏上限**，不是机器狗累计转动上限。原厂位姿提供正确初值、连续画面有重叠时，理论上可以连续经过较大转角；不能跳过中间画面而要求局部ICP找回任意朝向。

算法依据参考：[Open3D ICP 官方教程](https://www.open3d.org/docs/release/tutorial/pipelines/icp_registration.html)、[SciPy cKDTree 官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.cKDTree.html)。本实现是按当前依赖编写的实验模块，不是直接集成 Open3D 重建系统。

## 真实保存数据上的结果

使用 `20261027_201124_805102` 会话的7帧子集：

| 源关键帧 | 处理结果 |
| --- | --- |
| 1 | 作为初始参考 |
| 2、10、20 | 几何检查后保持原始位姿，不施加微小纠偏 |
| 30 | 拒绝候选纠偏并停止融合 |
| 40、50 | 本次精配准重放未继续处理 |

第30帧距第20帧约3.67秒，跨越了明显移动区间。拟议纠偏约2.39 cm、0.77°，但原有留出有效点只保留92.96%，低于95%要求。该现象说明候选更新不能通过当前质量判定，**不能证明纠偏一定错误，也不能证明原厂位姿一定漂移**。没有放宽阈值将它包装成成功。

证据：`evidence/reconstruction_experiments/20261027_refinement_final/replay_report.json`。当前真实数据不足以证明配准改善了移动模型，更不能宣称90°转身或整圈扫描已经通过。

## 补齐可重放数据

原会话只有7个原始关键帧，缺少明显移动区间的大多数中间画面，无法离线还原原先54帧的连续跟踪。因此新增 `tools/reconstruction_archive.py`，在电脑采集端按原时间顺序保存**每个已接受融合帧**到 `frames.jsonl`，保留原深度和位姿。旧的稀疏关键帧仍保留。

归档上限64 MiB，达到上限后标记 `truncated=true` / `complete=false`，不产生中间缺口后又继续追加。`summary.json`记录已归档帧数和完整性。该上限只限制额外归档；现有融合容量保护仍在。磁盘写入失败会让当前采集明确报错。

重放优先读取顺序归档，避免将稀疏关键帧重复处理；仅当归档完整、全部记录已处理且帧数与摘要一致时标记完整会话重放。旧7帧实验始终标记为子集。

## 验证与操作

本轮51项三维相关测试通过，新增16项覆盖鲁棒配准、退化平面、无重叠、较大错误初值、90°坐标旋转、完整四元数投影、块切换保留旧表面、容量/磁盘配额、原目录保护、坐标系切换、拒绝后停止融合及完整归档重放。合成90°测试是数学坐标变换检查，不能替代真实转身实验。

在项目根目录运行，输出目录必须是尚不存在的新目录：

```powershell
$env:PYTHONPATH = "tools;tests"
python -X utf8 -m unittest discover -s tests -p "*reconstruction*.py"
python -X utf8 tools/reconstruction_replay.py evidence/reconstruction/20261027_201124_805102 evidence/reconstruction_experiments/my_baseline --max-voxels 45000
python -X utf8 tools/reconstruction_replay.py evidence/reconstruction/20261027_201124_805102 evidence/reconstruction_experiments/my_refined --refine --max-voxels 45000
```

依赖：电脑上的 NumPy 和 SciPy（本轮实测SciPy 1.17.1）。重放入口没有SSH、ROS或运动调用。NPZ/归档/证据保留本地，不进入Git；交接时须另行复制所需数据。

## 下一次需要实机时的最短流程

1. 更新并重启电脑端8766采集服务，让完整帧归档生效；保留现有在线融合，精配准继续离线验证。
2. 原厂位姿和深度输入正常后，人工低速转动约30°并返回，录制连续重叠画面；不直接从90°跳变开始。
3. 用完整归档同时重放基线和精配准版本，比较同一组数据的留出残差、拒绝点、表面厚度及块边界影响。
4. 该阶段通过后接入网页可选精配准模式，再依次验证60°、90°和往返闭合。现在尚未具备宣称大角度转动一致性的证据。

本轮没有要求开机，也没有进行任何真实转动测试。
