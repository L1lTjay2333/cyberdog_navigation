处理的是**建模之前的深度帧和点云数据**，不是灰模减面或平滑。输入来自原始`frames.jsonl`，输出新的深度样本归档和去重确认点云；原始文件保持不变。没有连接机器人，没有修改采集、控制或网页8766代码。

## 当前流程

1. 验证压缩负载、相机内参、深度编码、原始时间戳和完整位姿；不允许跨世界坐标系/相机混合。
2. 深度限定0.15–4米，非有限值、无效值排除。
3. 在原始深度图3×3邻域检查支持。至少两个邻点深度差小于`0.03+0.005×深度`米才保留中心观测。只剔除，不将邻居平均回深度图，不插补空洞。
4. 按原采集方式每4个像素反投影，使用原时间戳四元数和位移变换到vodom。
5. 同一2厘米体素内合并重复观测。先算每帧体素内中心，再对不同帧等权平均，防止某一帧采样更密就支配结果。支持数按不同帧计，不按像素数量计。
6. 至少两个不同帧支持才进入确认候选。确认候选中，5厘米范围内至少还需3个确认邻点才进入主点云。
7. 输出主点云；单帧和孤立候选另存，不称它们全部是噪声。输出用于后续建模的衍生深度帧：只保留stride-4位置上通过共识检查的原始测量值，未保留位置置零。

邻域与离群点过滤的参考：[Open3D官方离群点剔除说明](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud_outlier_removal.html)。当前程序用NumPy和SciPy完成上述固定步骤，没有调用灰模清理模块。

## 输出和查看

目录：`evidence/offline_mesh_20261028/mixed_motion_gray/data_processed/`。该目录沿用现有离线查看服务的位置，处理程序不读取灰模文件，输入只有原深度归档和摘要。

| 文件 | 用途 |
| --- | --- |
| frames_spatial.jsonl | 仅进行深度邻域剔除后的中间数据 |
| frames.jsonl | 通过多帧及空间共识的衍生深度样本，供下一阶段建模 |
| points_candidates.ply | 体素合并后、共识筛选前的代表点 |
| points_processed.ply | 多帧确认和空间检查后的主点云，含frame_support属性 |
| points_processed.npz | 主点云、体素索引及帧支持数 |
| points_excluded.ply | 未进入主点云的候选，保留供复核 |
| processing_report.json | 逐阶段数量、阈值、输入哈希及限制 |
| summary.json | 衍生数据摘要，明确标记derived |
| view_points.html | 原始采样、处理后、排除候选的交互对照 |

当前8767离线服务下打开`/data_processed/view_points.html`。三个视图共用同一视角，各最多显示3万个抽样点；显示点数不代表磁盘完整点数。页面和预览JSON是本次另行生成的查看产物，CLI当前仅自动输出数据文件和报告。
